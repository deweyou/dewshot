# DewShot 使用统计、耗时与故障诊断 PRD

2026-11-24 · 首版需求。适用于原生 macOS 应用。

## 首版要回答的问题

1. 同意共享数据的安装中，有多少能从欢迎页走到第一次成功截图？如果流失主要发生在授权前，优先改授权引导。
2. 大家实际使用哪种截图或录屏方式？捕获后更常手动复制、保存还是打开成品？据此调整菜单栏和角落预览的操作顺序。
3. 用户点下快捷键、确认截图或停止录屏后，哪一步等得最久？区分普遍变慢和少量特别慢的操作。
4. 哪些故障会让用户拿不到成品？用 GA 识别频次和影响，用 Sentry 的源码堆栈定位原因。

沿用 Cubegin 的做法：参数用固定枚举，业务代码通过统一入口报告。GA 负责产品行为与耗时分布；Sentry 记录崩溃和可排查的关键失败。首版以安装为统计单位，不建立跨设备身份。

## 用户选择与数据范围

建议在欢迎页提供可选的「共享使用统计与故障诊断」，说明“帮助我们了解哪些功能常用、哪些操作较慢，以及应用在哪里出错”。初始关闭，截图录屏可直接使用。设置中可以随时更改。两端 SDK 的自动采集、崩溃处理和事件缓冲都服从同一个选择；同意前的行为不缓存、不补发。关闭后停止采集，丢弃尚未发送的数据；撤回前已经送达的数据不计作本地待发送记录。

GA 使用安装实例维度，不传邮箱、序列号、iCloud ID 或自建用户 ID。事件允许使用版本、build、环境和下表列出的枚举或数值。截图、录屏、OCR、按键内容、剪贴板、窗口标题、文件名及路径均不进入遥测。Sentry 禁用截图、附件、回放、默认个人信息和未经筛选的面包屑；保留符号化所需的模块及栈帧，过滤路径与自由文本。比如保存错误的本地提示会带目标路径，发送时映射成固定的错误类别。

## GA 最小事件原则

首版定义三个自定义事件。先写清楚要回答的问题和计数单位。能从现有事件及其参数推导的指标直接在报表计算。同一个业务阶段结束时只发一条 GA 记录，结果、耗时和失败原因随这条记录发送。不同时间发生、需要独立计数的步骤仍保留各自的观测点。

| 事件 | 一条记录代表什么 | 参数与触发条件 |
| --- | --- | --- |
| `setup_step` | 一次可观察的引导步骤 | `step=viewed` 表示欢迎页可见且已同意共享，附 `screen_access=granted/missing`。在页内开启共享时记当前展示一次，切换前后台不重复。`step=access_granted` 表示实际观察到权限从缺失变为可用。分别在发生时发送，才能统计停在欢迎页的安装。 |
| `capture_step` | 一次捕获阶段到达成功或失败终点 | `stage` 取下表前五项，附 `outcome`、`duration_ms`。入口阶段附 `entry` 和 `initial_mode`；成品阶段附最终 `kind`，录屏另附 `format`。同一次选区内切换模式不重复记入口。滚动中间帧及历史重开不产生成品记录。 |
| `capture_action` | 对成品的一次复制、保存、钉住或打开操作结束 | `action=copy/save/pin/open`、`source=preview/history/pinned/automatic`、`media=screenshot/recording`、`outcome`。保存按下表最后一项附耗时；相同文件复用记一次成功，可区分复用与新写入。自动复制只在实际执行时记，并与手动复制分开统计。 |

`outcome=success/failure`。最终失败时在相应记录附枚举 `reason` 和 `impact=blocked/degraded`。底层重试完成后只记最终结果；主动取消、忙碌拒绝、等待授权均不计故障。Sentry 对符合诊断条件的失败另收诊断报告。GA 的故障数只从 GA 的失败记录计数。

## 耗时参数

用单调时钟在本机计算非负整数 `duration_ms`。一次操作在内存中关联起止点，终态最多记一次，不上传关联 ID。异步排队、编码和 UI 调度计入用户实际等待的阶段。下表最后一行由 `capture_action(action=save)` 承载，其余各行由 `capture_step(stage)` 承载。

| stage | 起点 | 终点 | 分析维度 |
| --- | --- | --- | --- |
| `overlay_ready` | 应用收到并接受快捷键或菜单等捕获请求 | 目标屏上的选区窗口已显示、可以操作 | 入口、初始模式。被权限引导拦截的请求没有此样本 |
| `screenshot_preview_ready` | 用户确认普通截图选区或全屏截图，开始撤掉浮层 | 第一张可用的最终角落预览已显示 | 区域、窗口、全屏。包含浮层消失等待、捕获和预览前的处理；多屏只取首张 |
| `scroll_finalize` | 用户确认完成滚动截图 | 最终长图预览替换临时预览，可以复制或保存 | 手动或自动滚动。排除用户滚动和阅读的时间 |
| `recording_start` | 用户确认开始录制 | 录屏会话成功启动，HUD 进入录制状态 | MP4、GIF。此指标衡量启动反馈，不代表首帧已写入 |
| `recording_finalize` | 用户点击停止且请求被接受 | 编码器完成封装并返回成品文件 | 格式及录制时长分档。排除录制过程本身 |
| `save_to_folder` | 目标目录已获得授权，开始执行本次保存 | 成品写入结束，或确认已有相同文件可复用 | 媒体类型、操作来源；截图区分新写入与复用。包含目录扫描、内容比较和磁盘写入，排除文件夹选择器中的等待 |

同一阶段失败时，以返回最终错误为终点。未进入可计时区间的失败可以省略耗时，例如选目录时遇到系统错误。主动取消、等待系统授权、应用退出导致缺少终点，都不构造零毫秒或超时样本。滚动逐帧和录屏逐帧不上报。首版建议对已同意用户的上述阶段全量采集；若后续采样，需同步调整统计口径。

## 报表与决策

| 指标 | 首版口径 |
| --- | --- |
| 首次截图成功率 | 按安装去重。首次观测到 `setup_step(viewed)` 的安装中，24 小时内至少一次 `capture_step` 在 `screenshot_preview_ready` 或 `scroll_finalize` 阶段成功的比例。分母只取已满 24 小时的观察队列；已授权与缺权限分开看 |
| 周活跃安装 | 自然周内至少一次截图、长图或录屏成品阶段成功的安装数，即上述两种截图阶段加上 `recording_finalize`。用成品衡量活跃，排除仅常驻菜单栏的启动 |
| 成品使用 | 按媒体和入口展示手动操作次数、使用该操作的安装数；自动复制单独展示。同一成品可被多次使用，操作次数不解释为用户转化率 |
| 性能 | 按 build 和上表六个计时区间比较成功样本 P50、P95、样本数；失败样本单列。优先看 TestFlight 和相邻正式版本各自的分布 |

GA 注册需要筛选的低基数事件维度；毫秒数保留为数值。百分位必须基于逐事件样本，例如使用 GA4 的 BigQuery 事件导出，不能用日均值推算 P95。若首版未开通逐事件导出，增加固定耗时区间参数，在 GA 报表展示区间占比，标明为区间估计。首轮 TestFlight 建基线；样本不足时只列数量和观测值，不设没有依据的发布阈值。

## Sentry 与发布验收

首版覆盖原生崩溃、截图捕获失败、滚动截图无法生成成品、录屏启动或封装失败、保存读写异常。为可处理错误提供固定 operation、reason、impact 和 build；磁盘已满这类可预期情况可计 GA 频次，不必为每次发生创建 Sentry 诊断。Dev、内部测试和生产数据应可清楚区分；同一候选包从 TestFlight 晋升正式版时需验证环境路由，单凭生产 Bundle ID 无法区分两者。

| 验收项 | 通过条件 |
| --- | --- |
| 用户选择 | 在沙盒签名包中验证首次未选择、主动同意、撤回、重启四种状态。只有同意期间产生的数据进入相应测试项目，撤回后重启也不补发 |
| 产品事件 | GA 测试环境逐项核对事件名、参数和值。走通快捷键截图、双屏全屏、手动复制、自动复制、历史重复保存、录屏成功与取消，核对预期计数。例如关闭自动复制后，一次快捷键截图并手动保存成功应恰有三条自定义记录：选区就绪、截图预览就绪、保存成功。把保存改成写盘失败，第三条改记失败并附原因和耗时，总数仍为三条 |
| 耗时 | 用可控时钟验证六个阶段的成功、失败、取消、重复回调。真机故意停留在选区和文件夹选择器中，确认不会拉长截图处理和保存耗时；停止录屏后单独核对封装耗时 |
| 故障诊断 | 测试环境制造一次受控写入失败及一次测试崩溃。核对归类、build、dSYM UUID 与符号化源码行；检查服务端事件载荷中没有测试用敏感文件名、路径或附件 |
| 分发 | 核验商店沙盒包具有所需出站网络权限、SDK 配置和符号文件。核对 SDK 自动采集项、隐私清单、商店隐私披露及公开隐私政策，再发布带遥测的新 build |

首版共用一个默认关闭的共享开关。GA 随每条计时记录保存毫秒数和固定耗时区间，先用区间占比观察分布。开发、TestFlight 和正式版的项目映射见[开发指南](development.md#usage-analytics-and-diagnostics)。
